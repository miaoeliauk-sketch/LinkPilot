# 校准语料集

Day 2 校准阈值用的。**检测器判不准，后面全部白干**——`thresholds.json` 里每个数字都要靠这批语料定，不能拍脑袋。

## 需要多少

| 组 | 数量 | 谁来准备 |
| --- | --- | --- |
| `human/` 人稿 | 20 篇 | 只能人工收集，无法替代 |
| `ai/` AI稿 | 20 篇 | 让模型按常见提示词直接生成即可 |

两组数量要接近，否则误报率和召回率这两个指标会被样本比例带偏。

## 人稿的标准（这组最容易搞砸）

**必须是真人对着镜头说出来的话，扒下来的逐字稿。**

✅ 算数：
- 短视频/播客/直播切片的自动字幕导出，或者听打
- 保留口语原貌：重复、口头禅、不完整句、语气词，**都别删**
- 每篇 150–600 字（对应 30 秒到 2 分钟口播）
- 尽量来自不同的人、不同题材

❌ 不算数：
- 公众号文章、新闻稿、产品文案——这些本来就是书面语，拿来当"人稿"会把阈值调到"人写的也超标"，等于自己把误报率做上去
- 念稿式演讲、新闻联播播报——书面语出声念，不是口语
- 同一个博主的 20 条——那校出来的是"这个人的说话习惯"，不是"人类口语"

最后一条尤其重要：语料的多样性直接决定阈值是不是只对一个人有效。

## 文件格式

一篇一个 `.txt`，UTF-8，纯正文，不要标题、不要序号、不要 markdown。文件名随便，`001.txt` 或 `潘家园旧书.txt` 都行。

来源统一记在 `sources.tsv`，一行一篇，用 Tab 分隔：

```
human/001.txt	抖音 @某某	2026-03 存档
ai/001.txt	某模型	提示词：帮我写一篇60秒的手账好物口播
```

来源不用写得多详细，够以后回溯"这批语料从哪来的"就行。

## 攒好之后

```bash
pnpm calibrate   # 尚未实现，Day 2 落地
```

会输出两组在各项指标上的分布、当前阈值下的人稿误报率和 AI 稿召回率，以及建议的阈值取值。

验收线：**人稿误报率 ≤ 10%**（20 篇里误判不超过 2 篇），AI 稿召回率 ≥ 70%。前者是这个工具的生死线——把人自己写的句子标成 AI 写的，用户立刻就不信了。
