# 抖音视频批量逐字稿提取工具

从 `links.txt`（或图形界面里的输入框）批量读取抖音视频链接，自动下载音频并用 Whisper
转写为文字，最终输出每条视频的独立 txt 文件（带时间戳，方便对照原视频跳转）、一张封面图，
以及一份汇总 Excel 表格。

提供三种使用方式：
- **命令行版**（`douyin_batch_transcript.py`）：适合批量跑很多链接、需要断点续传/并发的场景
- **图形界面版**（`douyin_transcript_gui.py`）：不想用命令行的话，运行这个文件，打开一个窗口，
  粘贴链接、点"开始转写"就行，结果直接显示在窗口里
- **Excel 版**（`douyin_excel_transcript.py`）：如果你已经有一份抖音批量采集工具导出的 Excel
  （比如"作品网址"那种列名的表格），可以直接读这份表格里的链接，转写完写回同一份表格，不用再
  手动复制链接，见下面"从 Excel 表格批量转写"一节

## 功能特性

- 批量处理：一行一个链接，自动逐条处理
- 自动识别链接：可以直接粘贴 App 分享出来的整段文案（标题、话题标签、提示语都没关系），
  程序会自动挑出真正的链接；除了抖音链接，也认得直接指向视频文件本身的地址（`.mp4`/`.m3u8`
  结尾那种），配合下面"微信视频号"一节的浏览器脚本可以用来转写视频号内容（实验性，见下文）
- 尝试支持粘贴博主主页链接：如果粘贴的是一个账号主页（而不是单条视频），会尝试自动展开成
  该账号下所有视频的链接。**实测确认：当前版本的 yt-dlp 并不支持抖音（国内版）的用户主页链接**
  （会报 `Unsupported URL`），这个功能目前用不了，只能一条一条粘贴具体的视频链接。
  这不是配置问题，是 yt-dlp 本身没有对接抖音的用户主页/账号视频列表接口（TikTok 国际版有类似
  功能，抖音国内版没有）。如果以后 yt-dlp 更新支持了，这个工具会自动受益，不需要改代码。
  **变通方案**：见下面"从博主主页批量拿链接"一节，用浏览器脚本从网页里直接提取。
- 音频下载：使用 `yt-dlp` 下载并转码为 mp3，转写完成后自动删除中间音频（可用 `--keep-audio` 保留）；
  如果连原始视频文件也想要，用 `--keep-video`（图形界面版对应"同时保留视频文件"勾选框）
- 三种转写模式：
  - `local`：本地跑 `openai-whisper`，模型大小可选 `tiny/base/small/medium/large`，免费但慢；
    会自动给模型一句中文提示语引导它加标点、断句，并关闭"带上下文解码"以降低幻觉文字互相
    传染的概率（见下面"注意事项"）
  - `api`：调用任意"OpenAI 兼容"的语音转写接口，默认是 OpenAI 官方 Whisper API
    （`whisper-1` 模型），也可以通过 `--api-base-url` 换成 SiliconFlow 等第三方兼容服务，
    速度快很多，国内访问也更稳定
  - `bailian`：调用阿里云百炼/DashScope 的 Paraformer 实时语音识别，只需要一个 DashScope
    API Key，不需要额外开通存储服务
- 并发处理：可配置并发数，每个任务前随机延迟，降低被风控概率
- 失败重试：下载、转写失败自动重试（指数退避），多次失败后记录到失败列表并继续处理其它链接
- 断点续传：`processed_archive.txt` 记录已成功处理的链接，重复运行自动跳过
- 时间戳逐字稿：每条视频的 txt 文件里，每句话前面都会带上 `[分:秒]` 时间戳（形如
  `[00:12] 这是这一句的文字`），方便照着时间戳找到原视频对应位置。本地模式和百炼模式一直都
  能拿到时间戳；`api` 模式下大部分第三方服务也支持，若对方不支持则自动退回不带时间戳的纯文字
- 封面图：每条视频处理成功后，会顺手把封面图也下载保存到输出目录（文件名形如
  `<视频ID>_封面.jpg`）；下载封面图失败不影响转写结果，只会在日志里留一条提醒
- 汇总 Excel：包含视频链接、视频ID、转写文字、封面图、视频文件、转写状态、处理时间等列

## 安装依赖

```bash
pip install -r requirements.txt
```

或手动安装：

```bash
pip install yt-dlp openai-whisper openai pandas openpyxl requests dashscope opencc-python-reimplemented
```

另外需要系统安装 `ffmpeg`（用于音频转码），例如：

```bash
# Ubuntu/Debian
sudo apt install ffmpeg

# macOS
brew install ffmpeg
```

Windows 用户请看下面单独的"Windows 安装说明"一节。

> 说明：`openai-whisper`（本地模式）依赖 PyTorch，安装包较大；如果只用 API 模式，可以不装
> `openai-whisper`，程序只会在你选择 `--mode local` 时才检查该依赖。同理 `dashscope` 只有
> `--mode bailian` 才需要，只用 `local`/`api` 模式可以不装。

## Windows 安装说明

Windows 上没有 Homebrew，装法跟 macOS 不太一样：

1. **安装 Python**：去 [python.org](https://www.python.org/downloads/) 下载安装包，安装时
   **一定要勾选"Add python.exe to PATH"**这个选项，不然后面找不到 `python` 命令。
2. **安装 ffmpeg**：
   - 较新的 Windows 10/11 可以直接在命令提示符里运行：`winget install ffmpeg`
   - 或者去 ffmpeg 官网下载 Windows 版本，解压后把里面 `bin` 文件夹的路径加到系统环境变量
     `PATH` 里
3. **安装 Python 依赖**：打开命令提示符（cmd）或 PowerShell，`cd` 到项目文件夹，执行：
   ```
   pip install -r requirements.txt
   ```
4. 日常使用双击 **`start_gui.bat`** 即可打开图形界面（见下面）。

## 使用方法（图形界面版，推荐给不熟悉命令行的用户）

安装好依赖（见上面"安装依赖"/"Windows 安装说明"）之后，有两种打开方式：

**方式一：双击启动（装好依赖后日常用这个就行，不用再开终端/命令提示符）**

- **macOS**：双击文件夹里的 **`start_gui.command`**。

  > 第一次双击时，macOS 可能会提示"无法打开，因为无法验证开发者"——这是苹果对未签名脚本的
  > 常规拦截，不是文件坏了。这时候**不要直接双击**，改成：**右键点这个文件 → 选"打开" →
  > 弹窗里再点一次"打开"**。这样操作一次以后，以后就能正常双击打开了。
  >
  > 双击后会弹出一个终端窗口（这是正常的，脚本需要借助终端来运行），过几秒图形界面窗口就会
  > 打开；终端窗口可以放着不用管它，也可以缩小，处理过程中的报错信息也会打印在这个终端窗口里。
  >
  > 如果你用的不是系统自带的"终端"（Terminal.app），而是 iTerm2、Ghostty 这类第三方终端，
  > 双击有可能因为终端对中文路径的编码处理不一样而报"no such file or directory"（路径显示
  > 是一堆乱码）。这种情况下最简单的办法是**把整个项目文件夹放到一个不含中文的路径下**（比如
  > 直接放在 `~/douyin_transcript_tool`，而不是放在带中文名字的文件夹里），或者改用系统自带的
  > "终端"打开这个文件夹再手动运行 `python3 douyin_transcript_gui.py`。

- **Windows**：双击文件夹里的 **`start_gui.bat`**。

  > 双击后会弹出一个黑色命令提示符窗口（正常现象，脚本需要借助它来运行），过几秒图形界面
  > 窗口就会打开；这个黑色窗口可以放着不用管，处理过程中的报错信息也会打印在里面。如果双击
  > 后提示"'python' 不是内部或外部命令"，说明装 Python 时没有勾选"Add python.exe to
  > PATH"，需要重新安装一次并勾选这个选项。

**方式二：命令行启动（也可以，效果一样）**

```bash
python3 douyin_transcript_gui.py
```

Windows 上如果 `python3` 命令不存在，改用 `python douyin_transcript_gui.py`。

会打开一个窗口，两种输入方式二选一：

> ### ⚠️ 关于 "Fresh cookies (not necessarily logged in) are needed"
>
> 如果**整批都失败**、每条都报这个错，那**多半不是 Cookies 的问题，也不是升级 yt-dlp 能解决的**：
> yt-dlp 的抖音解析器本身在上游就长期处于损坏状态（见 yt-dlp issue
> [#9667](https://github.com/yt-dlp/yt-dlp/issues/9667)、
> [#16803](https://github.com/yt-dlp/yt-dlp/issues/16803)），官方尚未修复。
>
> **绕开的办法：用"视频源网址"而不是"作品网址"。**
> 采集类工具导出的 50 列 Excel 里通常有一列叫 **`视频源网址`**，存的是视频文件本身的地址
> （形如 `https://www.douyin.com/aweme/v1/play/?video_id=...`）。这类地址不走作品详情页那套
> 风控，可以直接下载。本工具的 Excel 模式**会自动优先用这一列**，哪一行为空才退回用
> `作品网址`；开始处理时日志里会写一行"表格里有'视频源网址'列，优先用它下载"。
>
> 所以，如果你的表格里**没有**这一列，或者这一列是空的，就还是会撞上同样的错误——
> 这时需要换一个能导出 `视频源网址` 的采集工具重新导一份表格。
>
> 另外注意：这类源地址是**带签名、会过期的**。表格放了很久再来转写，可能需要重新采集一次。

**方式一：手动粘贴链接**

1. 在"抖音视频链接"框里粘贴一个或多个链接（一行一个）
2. 选择转写模式（`local` 本地 / `api` 调 OpenAI 或 SiliconFlow 等第三方 / `bailian` 阿里云百炼）、
   模型大小、要用来读取 Cookies 的浏览器；`api` 和 `bailian` 模式对应的 Key/接口地址填在下面
   对应的输入框里（具体每个模式怎么填，见下面"三种转写模式怎么选"一节）。如果一直报
   "Fresh cookies... are needed"，说明自动从浏览器读取 Cookies 这条路在你的电脑上不稳定
   （常见于部分 macOS 系统的权限/加密限制），可以改用下面的**"Cookies 文件"**输入框，选中一份
   手动导出的 `cookies.txt`（用浏览器扩展比如"Get cookies.txt LOCALLY"登录抖音后导出），
   填了这个之后会优先用这份文件，不再走自动读浏览器那条路
3. 如果不只是要文字，还想把视频本身也下载下来，勾选**"同时保留视频文件"**（默认不勾选，
   只提取文字更快）
4. 点绿色的**"开始转写"**按钮
5. 等待处理，运行日志会实时显示在下面的"运行日志"框里
6. 处理完成后，"转写结果"框里会直接显示每条视频的文字，同时输出目录里也会生成对应的
   txt 文件（带时间戳）、封面图、汇总 Excel（可以点"打开输出文件夹"直接查看），勾选了
   "保留视频文件"的话还会多一个 `<视频ID>.mp4`

**方式二：直接选一份或多份 Excel 表格（比如批量采集工具导出的作品列表，不用再手动复制链接）**

1. 点链接框下面的**"选择 Excel 文件...（可多选）"**按钮，像平时打开文件一样选中你的表格；
   在弹出的文件选择窗口里按住 Cmd（Mac）或 Ctrl（Windows）可以一次选中多个 Excel 文件
2. 选好之后会忽略上面的链接框，自动按每份表格里的**"作品网址"**列取链接
3. 转写模式等其它设置跟方式一一样，填好后点**"开始转写"**
4. 转写结果会**直接写回每份 Excel 本身**（新增"逐字稿"列，并把"是否已经语音转写文案"标记为已完成）；
   同时每条转写成功的视频，还会额外在下面"输出目录"里生成一份独立的 txt 文件（带时间戳，文件名用
   表格里的"作品id"列）和一张封面图，方便单独查看/分享某一条；重复运行会自动跳过已经处理过的行（断点续传）
5. 选了多个文件时，程序会**按选中的顺序依次处理**，一份处理完再处理下一份，日志里会用
   "===== 开始处理第 X/Y 个文件 ====="标出每份表格的分界；不需要一份一份分开跑
6. 如果想改回手动粘贴链接的方式，点"清除，改回手动粘贴链接"

**中途想停下来？** 处理过程中"开始转写"按钮旁边会出现一个红色的**"停止"**按钮，点一下就会在
处理完当前这一条之后停下来（不会粗暴中断正在下载/转写的那一条）。两种方式都是每处理完一条就
立刻保存一次（Excel 方式存回原表格，手动粘贴方式每条视频的 txt 也是随转写随写盘），所以就算
不点停止、直接关掉整个窗口，之前已经处理完的部分也不会丢——重新打开、选中同一份（或同一批）
Excel 或者补上没处理完的链接，就能接着跑。选了多个 Excel 文件时，点"停止"会在处理完当前这一条
之后停下来，正在处理的这份文件里已经完成的行都已经保存好了，但排在后面还没开始处理的文件就不会
再继续处理了；下次重新选中同一批文件再跑，会自动跳过所有已完成的行，接着处理没跑完的部分。

> 用 Excel 方式时，建议自己先备份一份原表格，因为程序会直接修改你选中的这份文件。

`douyin_transcript_gui.py` 需要和 `douyin_batch_transcript.py`、`douyin_excel_transcript.py`
放在同一个文件夹里，因为它是直接复用这两个文件里的下载/转写/Excel 读写逻辑，不是重复实现的
另一套代码。

## 使用方法（命令行版）

```bash
python3 douyin_batch_transcript.py --links-file links.txt --output-dir ./output \
    --mode local --model-size small --concurrency 3
```

`links.txt` 一行一个抖音链接（也可以直接粘贴 App 分享出来的整段文案，程序会自动挑出链接）。

常用参数：

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `--links-file` | 链接文件路径 | 必填 |
| `--output-dir` | 输出目录 | 必填 |
| `--mode` | 转写模式 local/api/bailian | `local` |
| `--model-size` | 本地模式模型大小 | `small` |
| `--api-key` / `--api-base-url` / `--api-model` | api 模式相关参数 | - |
| `--dashscope-api-key` | bailian 模式的 DashScope Key | - |
| `--concurrency` | 并发数 | `3` |
| `--retries` | 每步失败后的最大重试次数 | `3` |
| `--retry-base-delay` | 重试的基础等待秒数（指数递增） | `2.0` |
| `--min-delay` / `--max-delay` | 每个任务开始前的随机延迟区间（秒） | `1.0` / `4.0` |
| `--keep-audio` | 保留中间下载的 mp3 文件 | 关闭 |
| `--keep-video` | 同时保留下载到的原始视频文件（`<视频ID>.mp4`），不只是提取文字 | 关闭 |
| `--cookies-from-browser` | 从指定浏览器读取 Cookies（`chrome`/`safari`/`firefox`/`edge` 等） | 关闭 |
| `--cookies-file` | 指定一个 Netscape 格式的 cookies.txt 文件路径 | 关闭 |

## 三种转写模式怎么选

- **不想花钱、不介意等一会儿**：用 `local`，本地跑 Whisper，完全免费，第一次用某个模型会
  自动下载模型权重（需要联网），之后就不用再下了。模型越大转写质量越好但越慢，默认 `small`
  是速度和质量的折中，机器配置好可以试试 `medium`。
- **想要更快、更准，愿意付一点点钱**：用 `api`，接 OpenAI 官方或 SiliconFlow 等第三方。
- **已经有阿里云百炼账号**：用 `bailian`。

## 从 Excel 表格批量转写（`douyin_excel_transcript.py`）

如果你已经有一份抖音批量采集工具导出的 Excel（比如列名里有"作品网址""是否已经语音转写文案"
这种字段的表格），可以直接用这个脚本：

```bash
python3 douyin_excel_transcript.py --excel-file 作品列表.xlsx --mode local
```

SiliconFlow（api 模式 + 自定义接口地址）：

```bash
python3 douyin_excel_transcript.py --excel-file 作品列表.xlsx \
    --mode api --api-key sk-xxxx --api-base-url https://api.siliconflow.cn/v1 \
    --api-model FunAudioLLM/SenseVoiceSmall
```

- 转写出来的文字写进新增的 **"逐字稿"** 列（`--transcript-column` 可改名）
- 断点续传：脚本用"是否已经语音转写文案"这一列判断某一行是否已经处理过，已经是 True 的行
  会自动跳过，重复运行不会重复转写。每处理完一行就保存一次文件，中途报错/中断也不会丢
- 转写失败的行，"逐字稿"列会写入具体的失败原因，"是否已经语音转写文案"保持不变，下次重新运行
  会自动重试
- 安全提醒：这个脚本会**直接修改你传进来的 Excel 文件本身**（原地追加/更新列），第一次用之前
  建议自己先备份一份

`douyin_excel_transcript.py` 需要和 `douyin_batch_transcript.py` 放在同一个文件夹里，是直接
复用后者的下载/转写逻辑，不是另一套实现。

## 从博主主页批量拿链接（浏览器脚本，变通方案）

因为 yt-dlp 不支持直接读取抖音用户主页，`douyin_profile_links_extractor.user.js`
换了个思路：不走服务器请求，而是在你自己已登录的浏览器里直接读取网页内容，
绕开这个限制。

安装和使用：

1. 给 Chrome/Edge 装一个 **Tampermonkey**（或 Violentmonkey）浏览器扩展
   （在应用商店搜索安装即可）。
2. 点 Tampermonkey 图标 → "管理面板" → "添加新脚本"，把 `douyin_profile_links_extractor.user.js`
   这个文件的全部内容复制粘贴进去，保存（`Ctrl/Cmd + S`）。
3. 打开任意一个抖音博主主页（网址形如 `https://www.douyin.com/user/MS4w...`），
   页面右下角会出现一个悬浮小面板。
4. 点"开始提取本页视频链接"，脚本会自动往下滚动页面加载更多作品（同时会顺手读取每条
   视频的点赞数、收藏数、发布日期），滚动稳定后自动停止。
5. **按条件筛选/排序**：面板上有这几个筛选项，都可以按需组合使用：
   - **最低点赞数 / 最低收藏数**：填门槛，只留下满足条件的视频（比如只要点赞超过 1 万的）
   - **发布日期区间**：只保留这段时间内发布的作品（比如只要最近一个月的）
   - **排序**：可以选"点赞从高到低"或"评论从高到低"，方便优先看爆款
   设置好之后点"应用筛选"，文本框里的结果会实时按条件更新。
6. 点"复制以上链接"，然后直接整段粘贴到 `links.txt` 或图形界面版的输入框里，正常运行
   转写即可——复制出来的每一行其实是"👍点赞数 ⭐收藏数 📅发布日期 + 链接"这种格式，
   前面的这些文字不用自己删，工具会自动只识别出链接部分，忽略掉其它文字。

局限说明：

- 只能提取"页面已经滚动加载到的内容"，作品特别多（几百上千条）时可能需要手动多点几次、
  多等一会儿滚动加载。
- 依赖当前抖音网页的结构，如果抖音改版导致提取不到链接，需要更新脚本里的选择器
  （欢迎反馈实际报错情况，方便针对性调整）。
- 点赞数/收藏数是从网页已经加载的数据里读出来的，个别情况下可能读不到（显示"未知"），
  筛选时这类视频会被当成 0 处理，也就是会被"最低点赞数 > 0"这样的条件过滤掉。
- 设置了发布日期区间时，如果某条作品读不到发布日期，会被直接排除（不确定日期就不算
  "在区间内"），不设置日期区间则不受影响。

## 输出结果

`output-dir` 下会生成：

- `<视频ID>.txt`：每条视频对应的逐字稿，每句话前面带 `[分:秒]` 时间戳（拿不到时间戳信息时，
  自动退回不带时间戳的纯文字）
- `<视频ID>_封面.jpg`：每条视频的封面图（下载失败不影响其它结果，只是没有这个文件）
- `<视频ID>.mp4`：加了 `--keep-video`（图形界面版勾选"同时保留视频文件"）才会有，原始视频文件
- `processed_archive.txt`：已成功处理的链接记录（断点续传用）
- `失败列表.txt`：处理失败的链接及原因（如果有失败的话）
- `汇总结果.xlsx`：包含全部处理结果的汇总表，列为：视频链接 / 视频ID / 转写文字 / 封面图 / 视频文件 / 转写状态 / 处理时间 / 备注

## 微信视频号（实验版，需要你帮忙测试）

`wechat_channels_video_sniffer.user.js` 是一个**实验性质**的浏览器脚本，尝试解决"视频号视频怎么
下载"这个问题。跟抖音那个脚本不一样，这个我没有条件在开发环境里用真实账号测试过，能不能用、
抓到的地址能不能实际下载，都需要你实际试过之后告诉我结果。

原理：视频号网页版播放视频时，真实的视频地址要么直接出现在网页的 `<video>` 标签里，要么通过
网络请求（fetch/XHR）从接口拿到。脚本会同时监听这两种情况，把"看起来像视频地址"的候选链接列在
右下角悬浮面板里，你自己复制出来试一下能不能直接下载/打开。

用法：

1. 装到 Tampermonkey 里（跟抖音那个脚本装法完全一样）。
2. 登录视频号网页版（`channels.weixin.qq.com`），打开一个视频号视频详情页，让它正常播放几秒。
3. 看右下角面板的"候选地址"列表，点每一条后面的"复制这条"，拿这个链接去新标签页或下载工具里
   试一下能不能正常打开/下载出视频文件。
4. 把测试结果反馈给我（能用的话是哪一条、完全没抓到东西、还是抓到的地址打不开），我再继续调整。

**抓到能用的地址之后怎么转写？** 好消息是这一步已经接进批量转写流程了：`douyin_batch_transcript.py` /
`douyin_transcript_gui.py` 的链接框现在**除了识别抖音链接，也会识别"直接指向视频文件本身的地址"**
（也就是 `.mp4` / `.m3u8` 这类结尾的链接，可能后面还跟着一串签名参数，没关系）。把从视频号脚本
面板里复制出来的那条地址，直接粘贴到链接框里，跟抖音链接一样正常跑"开始转写"就行，下载这一步
交给 `yt-dlp` 自带的通用下载器处理（不需要 yt-dlp 专门认识"视频号"这个网站，只要给到的是能直接
访问的媒体文件地址就行）。

> 同样要说明：yt-dlp 通用下载器处理直接视频地址这部分，是基于 yt-dlp 的公开文档能力做的，我这边
> 没有条件用真实视频号地址实测，效果同样需要你测试后反馈。

这个功能目前**只到"能不能拿到能用的视频地址"这一步需要你帮忙验证**，抓到地址之后的转写流程
复用的是已经跑通、测试过的现有批量转写逻辑，不需要你担心那部分。

## 注意事项

- 并发数不建议设置过高（默认 3-5），过高可能触发抖音的访问频率限制导致下载失败率上升。
- 本地模式转写速度和资源占用与模型大小正相关，`large` 模型对内存/显存要求较高，建议先用 `small`
  或 `medium` 测试。
- **本地模式转写偶尔会"幻觉"出跟视频完全无关的文字**（比如夹杂英文、其它语言乱码，或者一整段
  编造出来的内容）：这是 Whisper 本身在处理背景音乐、杂音、无人声片段时的已知问题，尤其是用
  `tiny`/`base`/`small` 这种小模型更容易出现，而且默认设置下这种"幻觉"会顺着上下文一直带到后面
  的段落，导致越转越离谱。程序已经关闭了"带上下文解码"（`condition_on_previous_text=False`）来
  降低这种连锁反应的概率，如果某条视频还是经常转出乱码，可以换成更大的模型（`medium`/`large`）
  再试一次，通常会好很多。
- 若 `yt-dlp` 因抖音页面结构变化导致解析失败，通常升级到最新版本即可修复：
  `pip install -U yt-dlp`。
- 程序对 `yt-dlp` / `openai-whisper` / `openai` 库的部分接口差异做了兼容处理（例如新旧版本
  OpenAI SDK 的调用方式、yt-dlp 返回信息字段缺失等），但如果这些库发生较大的破坏性升级，仍可能需要
  相应调整代码。
- Whisper（不管本地模型还是各家 API）转写中文时偶尔会输出繁体字或者简繁混杂，程序会自动把结果
  转换成简体字（依赖 `opencc-python-reimplemented`，装好依赖后默认生效，不需要额外配置）。
